# Lean Research Lab — Explore / Validate 双模式与 Codex 有界实验批次（兼容 V3.3）

> [English](../../../workflows/LEAN_RESEARCH_LAB.md) 为规范版本 | **简体中文**

## 目的及优先级
这是**精简执行协议**，不是新增 Agent、后台调度、审批机构或已实现的 CLI。每次用户触发的 SAE 工作周期中，GPT Mentor/Architect 负责数学假设、科学决定和最终验收，可向 Codex 一次交付**有界批量实验任务**。正式结论依[数学研究](../../../workflows/MATHEMATICAL_RESEARCH.md)，计算执行/发布依[计算实验](../../../workflows/GPU_EXPERIMENT.md)，PR 合并依[常设授权](../../../governance/STANDING_AUTHORIZATION.md)；用户最新停止指令及已固定的项目协议优先。

## 按结论类型划分双模式

| | `EXPLORE` 快速探索 | `VALIDATE` 正式验收 |
| --- | --- | --- |
| 目标 | 可行性、快速数值检查、排查设备/工具 | 有证据的正确性、加速或合并结论 |
| 启动 | GPT 记录可检验假设、最小 oracle 与任务范围；无 Scientist 签字，也无需先完成完整研究报告 | GPT 记录 `RESEARCH_READY` 或有界明确假设，并定义正式验收条件 |
| 执行 | 参考原型、小规模正确性测试、`PROBE_ONLY` GPU/TPU-XLA 探针可与数学研究并行 | 固定精确源码 SHA，运行相关参考/边界/随机数值检查与公平性能基准 |
| 证据 | 每批简短记录：源码身份（远程安装必须完整 SHA；本地未提交修改需标明 dirty 状态）、环境、命令、观察及真实 PASS/FAIL/NOT RUN/BLOCKED | 数学依据、被测 SHA、正确性与性能方法、设备/dtype/种子、带来源的实验清单和可复现证据 |
| GitHub | 复用现有 Issue/分支，**不要求每次探索都创建 PR 或三份完整报告**；留下值得保留的观察记录 | 通过审核的安全、精简证据关联代码 PR；可选 Publisher 须单独真实验证 |
| 结论 | **HYPOTHESIS / PROBE_ONLY / UNVERIFIED**，不称正式加速 | GPT 仅凭实测接受或拒绝；`NOT RUN` 不等于 `PASS` |

由 GPT 依据证据决定 EXPLORE → VALIDATE，**不是**新增 Scientist 审批。探针不能证明算法正确、TPU/XLA 全面支持或加速。

## 一个 Codex 任务 → 一个有界工程/实验批次
Architect 使用**一个现有或新建 Issue**，不再拆成连续的签核请求。简洁任务契约须包含：
1. **目标与模式：** 算法、可否证假设、预期输出与成败标准、关键数学假设和最小参考 oracle。
2. **源码与环境：** 仓库、工作分支/候选 SHA、真实本地/Colab CLI 权限、候选设备。正式远程实验必须安装精确 SHA；探索性本地 dirty 工作树需如实记录，不能冒充固定 SHA 的远程实测。
3. **有界执行：** 同时最多一个 Colab 活动会话，任务计划中**明确有限超时**，每类失败默认最多**三次自主修复尝试**（无进展应更早停止），成功/失败/中断都要清理资源。一个活动会话可按设备限制顺序运行多个实验；不允许无限循环或后台调度。
4. **批内自主循环：** 检查 → 最小实现 → 参考数值检查 → 有界 CPU/GPU/TPU 探针或准备就绪后的正式 Benchmark → 诊断/修复/复测。成功、重大数学歧义、真实资源耗尽、权限/安全/新增收费风险时停止；每次尝试无需创建新 Issue 或等待人类/GPT 再批准，但 **Codex 不自审 PR、不自行确认科学结论**。
5. **单次汇总交付：** 一个 Issue/PR 更新，含源码身份、命令、设备环境、数值证据、尝试与失败摘要、会话清理和下一阻塞；仅附必要产物，不重复写日报或每轮探索建 PR。

**不可越界：** 新订阅、充值、开启按量计费或既有权益外收费须用户明确许可；敏感非公开资料外发、外部账户/安全权限变更须单独许可；禁止直接写受保护主分支、Codex 自合并、默认 GitHub Actions 或付费 CI。真实工具权限、复现性、凭据筛查、错误和状态记录必须保留。

## 精简交接与学习
- **派单前：** GPT 做一次简短科研判断，提供一份完整可执行的批次契约；生态复用分析、参考实现和设备探针可按依赖并行。
- **批次后：** GPT 一次审查证据及风险，接受/合并合格 PR，或在**同一个 Issue**提出定向后续工作。数学证据失败就返回导师推导，不能装作已有完整证明。
- **必要时才写完整报告：** EXPLORE 只需简记；VALIDATE 正式验收时才按[三文档交接](../../../workflows/THREE_ARTIFACT_HANDOFF.md)组装数学、工程和实验材料，避免重复抄写测量表。
- **学习成果：** 对研究有价值时简述一条数学或数值发现，不强制另写学习日志。

## 实现状态
这里只是协议与任务契约，**不是**已实现的 Codex 自动执行器、Colab CLI、Publisher 或 Bootstrap。真实端到端批次、跨窗口 GPT–Codex 交接、TPU/XLA 支持均需单独实测，未验证时必须标 `NOT RUN`。
