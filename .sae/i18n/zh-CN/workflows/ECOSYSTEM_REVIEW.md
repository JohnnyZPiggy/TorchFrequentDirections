# 生态感知型架构设计 — 轻量级 Build-vs-Reuse 关口

> [English](../../../workflows/ECOSYSTEM_REVIEW.md)（正式规范） | 简体中文

## 时机与责任人

**责任人：GPT 总架构师。** 与 GPT 导师初步数学研究和 Codex 安全准备**并行**简短查找已有工具，不等待 Scientist 批准，也不因生态检索拖住可执行任务。依赖升级或小修复只需检查相关变动；不得跳过数学研究关口。

## 三步有边界检索

1. **优先 PyTorch 原生：** 按需调查 `torch`、`torch.linalg`、`torch.func`/`vmap`、`torch.sparse`、`torch.compile` 和张量算子，核实实际 API 与版本，优先支持矩阵/向量积、batch 和 matrix-free 的组合。
2. **针对性调查生态：** 原生功能不足时，检查直接相关且维护良好的 PyTorch 库，例如线性算子、可微求解器和领域工具。优先从官方文档/仓库核对**真实**许可证、维护情况、依赖和设备声明。
3. **已有算法参考实现：** 查询论文作者或上游开源代码，可作为正确性 oracle 或适配对象。区分参考基线、具有可再分发许可证的代码和生产级可移植实现。

**控制成本：** 小任务做简短调查，通常只列 **最多三个严肃候选**；仅在重大正确性、许可证或复杂性问题时深入研究。无法联网或读取资料时标记 **PARTIAL / UNVERIFIED**，指出未知问题并提出具体核验任务，不虚报调查过程。

## 选择规则

比较 **REUSE**（直接复用）、**ADAPT**（薄适配或组合）、**BUILD**（仅实现独特数学核心）。至少考虑：

- 与 GPT 已审推导的数学等价性、数值稳定性与误差容差；
- 许可证、维护状况、来源、传递依赖、固定 SHA 干净安装；
- 默认 CPU 可用、跨设备张量操作、dtype/autograd 需求；
- `torch.compile`、动态形状、主机同步及设备回退；
- 参考 oracle 测试、依赖版本约束、API 稳定性和公平 Benchmark。

**默认优先原生 PyTorch 或轻依赖复用**，但正确性、许可证、可复现性或跨硬件不满足时宁愿自己实现核心。既不为“创新”重造成熟基础设施，也不为节省几行代码引入笨重依赖。未经测试不得声称加速或兼容性。

## 只在现有报告留一小段

在 `templates/ENGINEERING_REPORT.md` 第 **2a 节 Ecosystem Review** 记录候选来源与日期、取舍、REUSE/ADAPT/BUILD 决定及未知事项。明显的原生算子复用可只写一行 `NATIVE_REUSE`。向 Codex Issue 交接接口/依赖版本、适配边界、CPU 数值/边界测试、干净安装、编译冒烟测试和回退方案。Codex 真实完成 CPU 检验，架构师审查，正式 GPU Benchmark 经技术准备关口后直接由 Codex 执行，**无需 Scientist 算力授权**；有界 `PROBE_ONLY` 设备探针可更早进行。

## 边界

不强制 GitHub Actions、不增加 Agent 或第四份报告、不跳过 CPU、不绑定芯片供应商、不编造 Benchmark、不自动升级固定依赖。资料无法核实就标未知，每轮结束仍按下一步口令协议交接。
