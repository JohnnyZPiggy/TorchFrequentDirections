# 下一步口令协议 — Agent 交接与手机一键继续

> 语言：[English](../../../workflows/NEXT_ACTION.md) | **简体中文**

## 目标

每次 GPT 导师、GPT 架构师或 Codex 工程师完成**实质性的一轮工作**，必须用简短的行动区告诉科学家下一步如何继续。这是**交互与交接规范**，不是新增 Agent、自动调度器、独立状态数据库，也不授权后台自行执行任务。

## 统一输出格式
每轮实质性工作以简短的 **SAE · 下一步行动** 结束（须填真实值，不保留占位符）：

> **SAE · 下一步行动**  
> **当前状态：** <已核实状态或 UNVERIFIED> · **证据：** <Issue/PR/报告/commit 或 NOT RUN>  
> **推荐：** <一条完整可复制的中文角色口令或 Scientist 行动> — <简短理由>  
> **备选：** <仅在真正不同的路径存在时零至两条>  
> **需要科学家：** <默认无；仅确需新增付费、非公开敏感披露、外部权限或不可逆操作>

依据**实时 GitHub 证据、优先级、依赖、阶段关口和实际权限**选择下一步，不沿用过期建议。通常：`RESEARCH_BLOCKED` → GPT 导师/架构师修订数学；`RESEARCH_READY` → 架构师；`CPU_IN_PROGRESS` → Codex；`CPU_VALIDATED` → 架构师审核实验准备；`GPU_READY` → Codex 按[实验默认执行](../../../workflows/GPU_EXPERIMENT.md)直接实验，**不要求 Scientist 算力批准或常设授权核验**；`GPU_BLOCKED` → 先本地排查。正确性/安全阻塞优先。

口令**不等于自动启动 Agent、分配算力或授予合并权限**。在 `GPU_READY` 前不得误要求正式性能验收；允许提前开展有界 `PROBE_ONLY` 设备探针，不泄露凭据、越过合并授权或承诺后台执行。[任务管理](TASK_MANAGEMENT.md)管理 Issue/PR 状态，本文件仅规定回复交接。

## Next-Action Completion Gate — 回复结束前自检（V3.3）

GPT 导师、GPT 架构师与 Codex 工程师完成**每轮实质性工作**后，在发送**最终用户可见回复之前**执行以下自检。即使研究、代码修改、实验或故障处理耗费大量上下文，也须在最终回复末尾保留交接区；需要缩短时优先精简正文，不省略交接。

1. **状态与证据：** 明确已完成、NOT RUN、UNVERIFIED、BLOCKED 的区别，引用可核实的 Issue/PR/报告/commit；不虚报结果。
2. **唯一推荐口令：** 若存在可继续的下一步，提供**一条完整、独立、可直接复制的中文命令**，写明对象与任务：`推进架构师工作：…`、`推进导师工作：…`、`推进工程师工作：…` 或 `Scientist：…`。不得保留占位符、模糊片段或建议无法实际调用的 Agent。
3. **有意义的多选：** 仅在存在真正不同且可执行的路线时，最多增加两条备选。推荐项始终只有一个；不得为凑数或换句话重复同一任务。
4. **不设人工审批队列：** 范围内科研、准备、工程与 T1/T2/T3 审查由 GPT 决定；Codex 按[实验默认执行](../../../workflows/GPU_EXPERIMENT.md)用现有算力。不得推荐等待 Scientist 科研、CPU/GPU、T3 或 PR 批准。保留真实权限、SHA、证据及新增收费/非公开敏感披露等外部边界；口令不等于实际执行。
5. **固定结尾：** 最后一节应为 **SAE · 下一步行动**，包含状态、证据、推荐/备选及确有必要的外部用户操作。如果不存在诚实可执行的下一步，明确写 DONE / BLOCKED / WAITING_FOR_EXTERNAL_ACTION；若有安全的恢复权限/审批动作，就以此作为可复制推荐。

### 复制粘贴与交互式多选降级

- **无论是否显示按钮，都必须显示完整文本口令。** 客户端实际支持复制/继续操作时，按钮关联的命令必须与可见文字完全一致；不得伪造按钮或声称已自动唤起外部 Agent。
- **不支持真实交互按钮的环境**（Codex CLI/桌面端、终端、纯 Markdown）须将每条推荐与备选口令放入**各自独立的纯文本代码块**，供直接复制粘贴，不要把不同选项放在同一个代码块。
- 若确实没有可执行动作，只报告完成/阻塞状态及外部前提，不能编造命令。本规则只是**回复层面的自检约束**，不是强制输出校验器；上下文丢失或工作中断仍可能导致遗漏。

## 示例（仅演示，不是实际项目状态）

**SAE · 下一步行动**  
**当前状态：** CPU_VALIDATED（示例）· **证据：** 示例 Issue #42  
**推荐：** `推进架构师工作：审核 Issue #42 的 GPU Readiness` — 先核验 CPU 证据。  
**备选：** `推进工程师工作：复核 Issue #42 的 CPU 编译日志`  
**需要科学家：** 常规科研、工程、实验、审查及合并均无需审批；仅真正涉及外部新增付费、非公开敏感披露或权限变更。

## 与现有协议关系

GitHub Issue/PR 仍是任务交接的唯一正式记录；本协议仅统一每轮结束时**告诉科学家什么**。根目录和项目 AGENTS、角色协议应链接此文件，不需要在每份角色协议复制全文。

## 角色恢复与防止出戏
每轮开始遵守[角色恢复协议](ROLE_RECOVERY.md)，核实角色、固定协议和实际权限；每轮结束通过本 Completion Gate。
