CLI methods omit an explicit timeout, but AuthorizedSession supplies **120 seconds** to each GET/POST; plain Requests default None is not the effective authorized default. Scalar 120 becomes connect/read 120, not a whole-command deadline. No aggregate AuthorizedSession max_allowed_time is set. Authentication precedes assignment and has library refresh/retry defaults; no real token refresh was tested. The controller's outer 120-second cap covers the whole command, so the original 120.025-second timeout does not locate the blocked stage or prove quota/device/network failure.

`status` does a remote assignment query on every invocation, even when local state is empty/cached; it may prune or update local records. PR 41's host report contains **71** status observations, all hardware null. That ad hoc wrapper is retired; its local polling block was removed and the wrapper was not run. It is outside the framework checkout, so its local removal is not a deployed repository change. The framework controller already has no status polling; new regression checks and usage guidance keep that policy explicit. No replacement polling service or frequent sessions queries are introduced. The effect of the historical observation traffic on allocation remains unproven.

Additional upstream edge case: empty-store sync catches an authentication SystemExit and returns an empty assignment list. A local mock reproduces it; an empty printed listing alone is therefore not unconditional authenticated-readback proof. This is not evidence that PR 41 had an auth failure and does not rewrite its accepted cleanup record. Propose a separately reviewed, narrowly scoped authenticated-readback improvement before a future live acceptance task; no installed vendor code or auth path is changed here.
